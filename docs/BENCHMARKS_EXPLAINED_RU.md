## Формулы, которые часто путают

Для каждого файла i: `r_i = uncompressed_i / archived_i`.

**Geometric mean ratio**: `exp(mean(log(r_i)))` — единичный статистический показатель *типичного относительного коэффициента на наборе файлов*.

**Aggregate ratio**: `sum(uncompressed_i) / sum(archived_i)` — насколько уменьшился весь объединённый объём байтов; размер маленьких и больших файлов влияет на итог. Их нельзя сравнивать без пояснения.

**Savings percent**: `100 * (1 - sum(archives)/sum(inputs))`. Не путать с multiplicative ratio и с процентным улучшением одного кодека относительно другого.

## Отдельный corpus Gabriel vs Brotli

Объём 139762 байта. 11 отдельных наборов, семь синтетических и четыре реальных. Времена получены в fresh Python processes, метрики — медианы, peak RSS включает процесс в целом. Профиль Gabriel MAX занимает на общем корпусе 35372 байта vs Brotli 33728 байт. Gabriel выиграл на smooth i32 (2907 против 4245), проиграл на source code (426 против 286). На random 8192 байтах дал expansion 66 байт.

**Разница по скорости:** 0.0102 MiB/s Gabriel MAX против 1.206 MiB/s Brotli и 4.155 MiB/s Zstd-19; это существенный проигрыш encoding по текущей Python реализации. Decode Gabriel ~496.6 MiB/s — измерение только на этом корпусе.

## Почему у бинарных и сжатых данных могут быть плохие результаты

Файл JPEG/PNG/MP4 обычно уже содержит внутреннюю компрессию и не обязан хорошо сжиматься повторно. Криптографически случайный поток не имеет предсказуемых повторов. Любой компрессор, который гарантированно уменьшает *каждый* N-байтный файл в M меньших байт без потерь, невозможен по принципу Дирихле. RAW — правильная ветка.

## Методика будущего независимого соревнования

Нужны независимые корпусы: Silesia/Canterbury или другие с лицензионной проверкой; логи/CSV/Parquet, исходники репозиториев без пересечения с train; реальные NPZ/ONNX/GGUF без утечки; уже сжатые файлы; pseudorandom; много маленьких/больших файлов; повторы версий с известной структурой.

Для каждого участника: исходный sha256, версия/commit, exact CLI, seed, CPU/GPU, RAM, OS, число потоков, archive bytes, headers, encode/decode wall, throughput, peak RSS, full restore success, time to first byte, random access p50/p95, corrupted-archive behavior.

Собрать **Pareto frontier** и доверительные интервалы, а не один маркетинговый score. Протокол прежде написать и зафиксировать, потом запускать тесты.

## Честные границы

`30×` geometric mean на фиксированном 11×32 KiB наборе **не** `30×` экономия на среднем дата-центре. Ни Tier-1, ни Gabriel results не доказывают средний выигрыш на больших enterprise datasets. Данные Tier-1 и Gabriel corpora имеют разный состав/метрики, поэтому их нельзя сливать в общую топ-таблицу без коррекции.
