# Технологии SYNERGY AI Compress — подробный инженерный каталог

> Названия технологий — названия семейства исследований. Ни одно название само по себе не доказывает превосходство над отраслевыми кодеками. Обратимость проверяется для каждого маршрута.

## 1. Простая модель задачи

Если вход `X` представлен N байтами, архив `C(X)` должен содержать достаточно информации для восстановления. В lossless режиме требуется `D(C(X))=X`, побайтовая проверка и SHA-256. В lossy-весах нейросетей точного восстановления *не требуется*, но требуется независимая проверка сохранения работы модели.

## 2. OMNIA Tier-1 v2: многокодековый маршрутизатор

### SPEED
Предпочитает RAW/Zstd-1/Zstd-3 и минимум безопасных преобразований. Цель — низкая задержка. Его нельзя оценивать по глубине перебора MAX.

### BALANCED
Собирает статистику локального потока (энтропия, доля нулей, ASCII, повторные блоки, лаговые разности) и допускает только правдоподобных экспертов. Использует маршруты текста, чисел, версий и структуры. Результат 27,235× на фиксированном Tier-1 — не общий ratio произвольного набора.

### MAX
Выбирает минимальный реально измеренный архив из набора RAW, нескольких Zstd/Brotli/zlib/LZMA, delta/shuffle/lag-XOR, version-XOR, RLE, BIP39 и собственных экспертов. По 11 файлам 30,336× геометрического среднего; время существенно выше скоростных профилей. `MAX` не есть автоматически оптимум мирового пространства всех преобразований.

## 3. Gabriel-Horn SGH1: зачем предиктор

Гладкая последовательность `100, 101, 102` имеет крупные сами значения, но маленькие разности `100, 1, 1`. Обратимый delta-предиктор хранит начальное значение и остаток. Для соседних версий XOR часто оставляет длинные участки нулей. Gabriel перебирает такое преобразование и оболочки значимости, затем применяет обычные entropy-кодеки.

Нужны не только короткие архивы: для хранилища БД важны `decompress_range`, индекс, амплификация доступа и глубина цепочки ссылок. Архив, который экономит 2% диска, но требует десятки секунд извлечения одной записи, может оказаться экономически непригоден.

Важный нюанс: частичное bit-plane-восстановление после нелинейного предиктора не обязано давать простой численный bound на итоговые восстановленные значения. Поэтому progressive preview отделяется от доказательства точного восстановления.

## 4. GRAAL-IGC / Graph-AI / RSX: графы связей

Серия `project-v1`, `project-v2`, `project-v3` содержит общие блоки и редактируемые фрагменты. Ресурс `C(X1, X2, X3)` может использовать content-defined chunking и ссылки на одинаковые блоки, что помогает при журналировании версий, но требует контролировать глубину ссылок, целостность и независимый доступ к одной версии.

Graph-AI предлагает кандидатов и маршруты. Истиной остаётся детерминированная проверка исполнителем. SimHash/ML-сходство нельзя путать с byte equality: похожий блок **не идентичен**.

## 5. SABF-X / PBM / HACE / UMC / EGD

- SABF-X: сжатие с ограниченным перебором и ранним отказом от бесперспективных вариантов; полезно для низкой задержки.
- PBM-39X: эффективный специализированный BIP39-ориентированный маршрут только при корректном словаре.
- HACE-X: каскад экспертов; риск — передача слишком большого объёма данных через дорогие стадии.
- UMC-256: модель минимальной длины описания с набором проверяемых преобразований, а не буквальная «кодировка 256 смыслов».
- EGD-256: tournament/многодвижковый исполнитель, который должен учитывать полную цену и correctness.
- GRAAL-AIS: ветвь хранения объектов/версий модели с селективным восстановлением, но она не доказывает корректность нейросети после lossy квантования.

## 6. BIP39: почему не универсальный метод

Официальный словарь BIP39 содержит 2048 слов, индекс помещается в 11 бит. Если весь поток состоит из этих *точных* слов и формат позволяет однозначный разбор, можно заменить слова индексами. На произвольных байтах, неизвестных словах, других языках или нарушенных границах слов такой маршрут не должен применяться. Это специализированная без потерь трансформация.

## 7. Lossless ModelStore и checkpoint storage

Для GGUF/ONNX/NPZ важны границы тензоров, имена параметров, версия структуры, ссылочный граф и точная реконструкция. Если первичное представление весов уже сильно изменено квантованием, архив без потерь поверх него лишь сжимает *этот квантованный поток*. Не следует дважды засчитывать выигрыш первичного lossy-кодирования и lossless-оболочки.

## 8. DWE: полученная отрицательная информация

Whole-row DWE представлял строку одним из 16–128 прототипов и нормой. Условный размер 2445× меньше BF16 для K=16 не означает сохранения функции матрицы. На реальных весах Mistral-Nemo-12B cosine/NMSE/activation relative L2 были неудовлетворительными. В коде изначально была также отдельная ошибка с насыщением signed 2-bit-центроида в `[0,3]` — потеря отрицательной части.

## 9. PQ/RVQ: перспективнее, но валидировать дальше

При PQ каждая строка делится на короткие блоки, каждый блок получает кодовый индекс. RVQ кодирует остаток дополнительными стадиями. Это улучшает геометрию аппроксимации по сравнению с whole-row, но даже на 0,75–1,5 bpw ошибка выходных активаций остаётся существенной. Нельзя называть модель «действительно работающей в 0,38 bpw» до тестов полного checkpoint.

### Следующий experimental protocol

1. Чётко зафиксировать ревизии checkpoint и calibration corpus; train/OOS исключает подглядывание.
2. Измерять first-order tensor error, random и реальные hidden-state activation loss.
3. Использовать activation-aware/importance-aware weighting, защиты outlier, layer-specific bit allocation.
4. Материализовать *полный* checkpoint с декодером, реально запускать модель.
5. Проверить PPL, downstream accuracy, latency, tokens/s, RAM/VRAM и качественную деградацию.
6. Сравнить при одинаковом объёме полезной нагрузки с сильными внешними методами.
7. Честно сохранить FAIL, если качество не прошло.

## 10. Выбор технологии по требованию

| Тип нагрузки | Первичная гипотеза | Контроль |
|---|---|---|
| Исходный код / JSON | Brotli / OMNIA | размер + скорость |
| Телеметрия | delta/shuffle/Zstd, Gabriel | random access + storage |
| Related versions | version XOR / graph chunks | корректность ссылок + rollback |
| Sparse bytes | RLE + Zstd | overhead на смешанном потоке |
| High entropy | RAW | overhead и целостность |
| LLM checkpoint | Lossless container; quantization отдельно | fidelity и full-model eval |
