# SHTENCO Gabriel Horn Codec

`GabrielHornEngine` — самостоятельный lossless-движок формата `SGH1`, построенный на разделении двух цен архива:

- **volume** — фактическое число байтов архива;
- **surface** — число активных оболочек, вычислительная работа, зависимости между блоками и цена выборочного доступа.

Он не утверждает, что конечный файл содержит бесконечное количество независимой информации. Несжимаемые данные сохраняются буквально. Аналогия с Рогом Гавриила используется как принцип организации: конечное ядро плюс последовательность всё менее значимых остаточных оболочек.

## Математическая модель

Для кандидата кодирования `c` минимизируется

```text
J(c) = B(c) + λs·S(c) + λw·W(c) + λd·D(c),
```

где:

- `B` — полный размер записи с метаданными;
- `S` — число реально активных significance-shells;
- `W` — оценка работы преобразования и декодирования;
- `D` — глубина ссылочной зависимости.

При `surface_weight=work_weight=0` выбирается строго минимальный архив. Положительные веса позволяют отказаться от ничтожной экономии байтов ради более дешёвого доступа.

Байт преобразованного остатка раскладывается на восемь оболочек значимости:

```text
r = Σ b_k·2^k,  k=0..7.
```

При чтении только старших `p` оболочек нормированная покоэффициентная граница хвоста равна

```text
ε(p) ≤ (2^(8-p)-1)/255.
```

При `p=8` восстановление строго точное.

## Что делает движок

1. Делит поток на блоки и в профиле `max` перебирает несколько размеров блока.
2. Для каждого блока перебирает обратимые модели:
   - identity;
   - delta первого и второго порядка;
   - XOR-предикторы с лагами 1…1024;
   - byte-shuffle ширины 2/4/8/16;
   - dyadic Gabriel/Horn lifting по масштабам 1, 2, 4, ...
3. Сравнивает обычное entropy-кодирование и раздельное кодирование восьми bit-plane оболочек.
4. Для каждой оболочки выбирает constant-zero, constant-one, raw bit-pack, RLE, Zstandard или zlib.
5. Заменяет точные повторные блоки ссылками.
6. Строит индекс `offset/length`, позволяющий извлекать диапазон без полной распаковки.
7. Хранит исходный размер и SHA-256 и проверяет их после полного декодирования.

## API

```python
from compression_lab.gabriel_horn_engine import GabrielHornEngine

engine = GabrielHornEngine(profile="max")
archive = engine.compress(source_bytes)
restored = engine.decompress(archive)
assert restored == source_bytes

fragment = engine.decompress_range(archive, 1_000, 5_000)
info = engine.inspect(archive)
preview = engine.decompress_progressive(archive, precision_bits=5)
```

Профили:

- `speed` — минимальный перебор;
- `balanced` — несколько размеров блока и полный набор основных моделей;
- `max` — максимальный перебор размеров, лагов, lifting-уровней и оболочечных вариантов.

## Контейнер SGH1

Контейнер содержит:

- magic/version;
- исходный размер;
- размер и число блоков;
- SHA-256;
- фиксированный индекс блоков;
- записи `RAW`, `ENTROPY`, `SHELLS` или `REFERENCE`.

Никакая модель не принимается «по эвристике»: в архив попадает только кандидат с лучшей полной стоимостью. На высокоэнтропийном потоке это означает переход к `RAW` без попытки выдать расширение данных за сжатие.

## Ограничения

- Bit-plane preview предназначен для анализа; после нелинейно распространяющих предикторов ошибка младших оболочек может распространяться по восстановленному блоку.
- Zstandard-архивы требуют пакет `zstandard`; при его отсутствии кодировщик использует переносимый zlib и помечает backend в контейнере.
- Формат оптимизирует отдельные байтовые потоки. Межфайловый словарь и content-defined chunking должны добавляться на уровне будущего файлового контейнера, а не нарушать блоковый контракт `SGH1`.
